## Context

The view-model in `crates/app/src/lib.rs` (`architecture.md`, "manhwa-cropper"):
a pure `Model { state: AppState, output_dir: Option<PathBuf> }` whose
`handle(&mut self, Event) -> Vec<Command>` owns every rule in
`docs/wiki/design/components.md`, "Rules the view-model owns", and every
user-visible string is produced here from the frozen table in
`docs/wiki/design/voice.md`, so egui (MC-015) only paints. No egui type
appears in this file. Effects are returned as data (`Command`) so the tests
assert them without threads or dialogs.

Gate that fails if this breaks: `unit`.

## Acceptance criteria

- **AC-1** - Given `Settings { output_dir: None }`, when `Model::new(settings)` runs, then `state == Idle` and `output_dir == None`; given `Some(p)`, then `output_dir == Some(p)`.
- **AC-2** - Given `output_dir == None`, when `FilesDropped(vec![a.png])` is handled, then `state == Error { message: "No output folder chosen. Choose one, then drop the files again." }` and no commands are returned.
- **AC-3** - Given `output_dir == Some(out)` and `state` is `Idle`, `Done` or `Error`, when `FilesDropped` with `n >= 1` paths is handled, then `state == Processing { done: 0, total: n }` and the commands are exactly `[StartBatch { inputs, out_dir: out }]`.
- **AC-4** - Given `Processing`, when `Progress { done: 3, total: 10 }` is handled, then `state == Processing { done: 3, total: 10 }`; when `Finished(summary)` is handled, then `state == Done { summary }`; neither returns a command.
- **AC-5** - Given `FolderChosen(p)`: in `Idle`, then `output_dir == Some(p)`, state stays `Idle`, commands are `[SaveSettings(Settings { output_dir: Some(p) })]`; in `Done { summary }`, then the summary is kept and the same command is returned; in `Error`, then `state == Idle`, `output_dir == Some(p)` and the same `SaveSettings` command is returned; in `Processing`, then nothing changes and no command is returned.
- **AC-6** - Given `Processing`, when `FilesDropped` is handled, then nothing changes and no command is returned; given any state, when `FilesDropped(vec![])` is handled, then nothing changes and no command is returned.
- **AC-7** - Given `Processing`, when `Failed("disk full")` is handled, then `state == Error { message: "Cropping stopped: disk full. Drop the files again." }`.
- **AC-8** - Given a `RunSummary` with 10 cropped, 0 flagged, 0 failed, when `result_line(&summary)` runs, then it returns `"10 cropped, 0 flagged"`; with 7 cropped, 2 flagged, 1 failed, then `"7 cropped, 2 flagged, 1 failed"`.
- **AC-9** - Given each outcome, when `row_text(&FileResult)` runs, then the text is `"<basename> — <reason>"` (space, U+2014, space) with reasons `Uniform -> Blank`, `NoBorderFound -> No border`, `LowContent -> Low content`, `Ambiguous -> Ambiguous`, `Unsupported -> Unsupported format`, `DecodeFailed -> Unreadable`, `Failed -> Not written`; and `rows(&summary)` lists only flagged and failed results, in input order.
- **AC-10** - Given a folder is known, when `dropzone_text(&model, hovering: bool)` runs, then it returns `"Drop images here"` in `Idle`/`Done`/`Error`, `"Release to crop"` when hovering in those states, `"Cropping…"` in `Processing`; given no folder, then `"Choose an output folder, then drop images here"` whether hovering or not. `path_text` returns the full path or `"No output folder chosen"`; `progress_text` returns `"3 of 10"`.

## Model guidance

Model: default. Oracle partition: everything is **mechanical** or
**settled** (the strings are frozen in `voice.md`; read them out
character for character, including U+2026 and U+2014). Pin the shapes:
`AppState { Idle, Processing { done: u32, total: u32 }, Done { summary: RunSummary }, Error { message: String } }`,
`Event { FilesDropped(Vec<PathBuf>), FolderChosen(PathBuf), Progress { done: u32, total: u32 }, Finished(RunSummary), Failed(String) }`,
`Command { StartBatch { inputs: Vec<PathBuf>, out_dir: PathBuf }, SaveSettings(Settings) }`,
all deriving `Debug, Clone, PartialEq`.

## Design notes

Nothing is painted here; this story implements the "Rules the view-model
owns" list in `docs/wiki/design/components.md` and produces every string in
the frozen table of `docs/wiki/design/voice.md`. MC-015 must be able to paint
the `Model` without touching a string literal, so every text the window can
show has a function here.

**Rule to criterion.** `FilesDropped` with no folder → `Error{error.no_folder}`,
no command (AC-2). `FilesDropped` while `Processing` is ignored silently, no
message (AC-6; ratified designer decision 1 - the disabled drop-zone look and
`dropzone.busy` in MC-015 are the only signal). `FolderChosen` keeps a `Done`
summary and clears an `Error` to `Idle` (AC-5); in `Error` it should return
the same `[SaveSettings]` command as in `Idle`, since the folder was the usual
cause of the error and the user has just fixed it - AC-5 is silent on the
command in `Error`, so the test should assert it, not leave it unspecified.
`Failed{detail}` → `Error{error.run_failed}` (AC-7).

**Strings, by key.** `dropzone_text` → `dropzone.no_folder` /
`dropzone.ready` / `dropzone.hover` / `dropzone.busy` (AC-10; with no folder
the hover flag is ignored and `dropzone.no_folder` is returned).
`path_text` → the full path via `Path::display()` as Windows shows it, no
quoting, no truncation (left-truncation is MC-015's painter), or
`folder.none`. `progress_text` → `progress.count`. `result_line` →
`result.line` plus `result.failed_suffix` only when `failed > 0`
(AC-8; `12 cropped, 0 flagged, 0 failed` is invalid). `row_text` →
`list.row` with the seven `reason.*` words (AC-9); `{filename}` is
`path.file_name()`, extension included. Tests should copy the bytes from
`voice.md`: `Cropping…` is U+2026, the row separator is space U+2014 space,
and the two error messages end in a full stop while every label does not.

**`{detail}` placeholder.** `voice.md` strips a trailing full stop from the
engine's detail so `error.run_failed` never reads `…disk full.. Drop…`. AC-7
uses `"disk full"` with no stop; the test should also cover
`Failed("disk full.")` producing the identical message. That is a second
case under an existing criterion, not a new one.

**`error.folder_unwritable` has no producer.** No event in this story's
`Event` enum carries an unwritable output folder, so no `handle` path yields
that string. `components.md` says an unwritable folder is reported in the
slot at drop time. Either the runner reports it as `Failed(detail)` (the user
then reads `Cropping stopped: …`, which is acceptable but not the designed
message) or a later story adds an event. Raised for the Lead PO; not worked
around here.

**Send-to fallback.** `Model::new(Settings{output_dir: Some(fallback)})`
(AC-1) is how MC-016 makes the resolved `cropped` folder appear in
`path_text` from the first frame. The model does not distinguish a remembered
folder from a fallback; that is MC-016's job, and it must not emit
`SaveSettings` for a fallback.

Keyboard, tokens, states: none apply - no widget exists in this crate file.
