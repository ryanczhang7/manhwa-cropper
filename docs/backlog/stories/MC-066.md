## Test plan

**The mechanism, stated as two claims with their controls (oracle-free
part).** Read out of the stages on both screenshots (`trim_uniform` →
`content_box` → `trim_within` → `textured_box` → `page_column` → `locate`),
RED found **two causes, one per screenshot**. The textured video is the cause
of `f18`'s shape and **not** of `f13`'s.

- **`f18`, stage 3c picks the video.** `content_box` peels only the 3-column
  strip at the right edge, so the rect is `0..2557`. Over the central band
  (rows 288..1152) the textured runs are `0..6`, `651..1167` (the page, 517
  wide), `1829..2544` (the video, 716 wide) and `2548..2556`.
  `edges::widest_textured_run` takes the widest, the video. The widening
  takes the seam column 1828, and the page column is `1828,0 717x1440`.
  `locate` beside it returns `None`, so the rows stay `0..1440`.
- **`f13`, stage 2 peels the page's left margin, and stage 3c's interior
  rule then refuses.** The left margin is one value (11) from column 0 to
  634: 635 columns, 0.248 of the width, under `chrome_max_extent` (0.30).
  Nothing textured sits at the left image edge (`f18` has `0..6`, MC-052's
  `01_22_45` has `0..6` and `00_58_06` a seam at 7). So the first strong
  column line is the page's own left edge, and `content_box` peels `0..634`
  as a chrome strip (`removed` = `[Left, Right, Bottom]`, rect `635..2557`,
  rows `0..1400`). The widest run is then the page (`635..1167`; the video
  `1820..2221` is 402 wide), but it starts on the rect's first column. The
  interior rule in `page_column` ("a page column that reaches either end of
  `within` has no page margin on that side") hands back the whole rect,
  `635..2557`.

Shown, not narrated, three ways:
1. **The AC-4 generated scenes**
   (`crates/core/tests/page_column_second_window.rs`). One geometry with two
   switches, the left edge (textured sliver / flat to column 0 under 0.30 /
   flat past 0.30) and the block (wider than the page / narrower / none).
   Measured on this tree:

   | left edge | block | crop today (m0) | role |
   |---|---|---|---|
   | sliver | wide | `915..1272`, rows `0..720` (second window) | `f18` cause on: **red** |
   | flat | wide | `915..1272`, rows `0..720` | both causes: **red** |
   | flat | narrow | `320..1278`, rows `58..700` (both windows) | `f13` cause on: **red** |
   | flat | none | `320..1278`, rows `58..700` (both windows) | `f13` without any block: **red** |
   | sliver | narrow | `320..584`, rows `58..700` | `f18` cause off: green |
   | sliver | none | `320..584`, rows `58..700` | `f18` cause off: green |
   | flat past 0.30 | narrow | page | `f13` cause off: green |

   The stage outputs on the scenes match the real ones: the same `removed`
   sides, the same `locate` decline on the wide-block scenes, and the same
   rects (`f18`: page column = video run plus the seam; `f13`: rect = page
   start to just inside the second window's scrollbar).
2. **Two controlled experiments through the public API, no source touched.**
   Neither is a proposed fix. `chrome_max_extent` is a settled `Tuning`
   field, and moving it is exactly the threshold sweep the story forbids.
   - `detect` with `chrome_max_extent: 0.24` (`f13`'s margin, 0.248, is then
     not peelable). Real `f13` crops to **`635,115 533x1277`**, exactly the
     re-pinned margin-0 row below, with `removed` `[Right]` only. Real `f18`
     is unchanged, `1828,0 717x1440`. Generated: both flat-left scenes go to
     the page `320..584`, rows `58..700`, and both wide-block scenes stay on
     the video.
   - `page_column` handed the reader's window only (columns `0..seam`). Real
     `f18` gives the page `651..1168`, and `locate` beside it returns
     `115..1399`, the furniture rows. Real `f13` gives `635..1168`.
     Generated: every scene gives `320..584`.

   So the two causes are separate. Each experiment cures exactly the scenes
   its cause claims.
3. **The corpus premises** (`corpus_second_window.rs`): the seam columns,
   and the single-value margin columns beside each mark.
