## Context

The brief's performance constraint, made a gate: a batch of 100 screenshots
between 1080p and 4K completes in under 10 seconds on the user's machine.
The test lives in `crates/engine/tests/perf.rs`, is `#[ignore]`d so
`cargo test --workspace` (the `unit` gate, debug build) does not run it, and
is run in release mode by the `integration` gate
(`cargo test --workspace --release -- --ignored`). That gate is optional for
the repo and `slow`, so this story requires it in its frontmatter; without
that, every required gate passes with this story's only claim unrun.

Fixture generation (100 PNGs written to a temp dir) is excluded from the
timed region and may itself take a while; that is why the gate is slow.

Gate that fails if this breaks: `integration`, required by this story.

## Acceptance criteria

- **AC-1** - Given 100 RGB8 PNGs generated from recipes with uniform borders and a chrome band - 40 at 1920x1080, 30 at 2560x1440, 30 at 3840x2160 - in a temp dir, when `batch::run` processes them into another temp dir, then the wall time of `run` alone is below 10.0 s on this machine, and the measured time is written into `## Notes` by the orchestrator after the gate run.
- **AC-2** - Given the same run, when it completes, then 100 outputs exist and each decodes to the dimensions of its recipe's art rect plus `2 * margin_px` on each axis. *Control on the metric:* a stub that copied files without cropping would beat the clock and fail this assertion, so the time is measured on real work.
- **AC-3** - Given the same run, when it completes, then `failed() == 0` and `flagged() == 0`.

## Model guidance

Model: default. Oracle partition:

- **Settled**: the 10 s budget and the 40/30/30 mix.
- **Mechanical**: AC-2 and AC-3.
- **Oracle-free**: the timing itself. If the budget is missed, that is a real finding for GREEN (parallelism, decode settings, luma conversion cost), never a reason to reduce the image count or resolution. A test whose own overhead (fixture generation, decoding for AC-2) is inside the timed region is wrong; keep the timer around `run` only.

## Out of scope

Benchmarks on other hardware, a `ci-factor` line (there is no CI runner for
this gate yet), JPEG and WebP timing (PNG decode is the expensive case),
memory usage.
