## Context

The brief's section 7 as a test: zero clipped panels across the corpus, and
at least nine in ten needing no manual fix. Runs the real pipeline
(`process_file` from MC-008/MC-009) over every corpus entry (MC-018) in an
`#[ignore]`d test under `crates/engine/tests/corpus.rs`, executed by the
`integration` gate in release mode, which this story requires. This is the
story where `Tuning::default()` may change: every constant in
`architecture.md`'s table was settled for RED on synthetic fixtures, and
this is the evidence that re-settles them. A constant change is a source
change under GREEN; record the before/after numbers in `## Notes`, and if
an *acceptance criterion* has to move, that is an `## Amendments` entry
approved by the user, with the orchestrator's own reproduction.

Gate that fails if this breaks: `integration`, required by this story.

## Acceptance criteria

- **AC-1** - *Zero clips.* Given every corpus entry with an expected rect, when processed, then for each entry whose outcome is `Cropped { rect, .. }`, `rect` contains the expected rect entirely (`rect.x <= e.x`, `rect.y <= e.y`, `rect.x + rect.w >= e.x + e.w`, `rect.y + rect.h >= e.y + e.h`). One violation fails the test and names the file and the offending side. *Control on the metric:* with every expected rect widened by 1 px on the top before comparison, the check must fail on at least one entry (recorded in the handoff; if it does not, the detector's margin is hiding the comparison and the control must move to 4 px).
- **AC-2** - *Nine in ten.* Given every corpus entry, when processed, then at least 90% are *right*: an entry with an expected rect is right when the outcome is `Cropped` and `rect` lies inside the expected rect expanded by `margin_px + 8` px on every side (AC-1 having held); an entry with `"expect": "flag"` is right when the outcome is `Flagged`. A flagged entry that expected a rect is a miss, and a cropped entry that expected a flag is a miss. The test prints a per-file table (file, expected, got, right/miss, reason).
- **AC-3** - Given the run, when it completes, then `failed() == 0` - every corpus file is readable and writable.
- **AC-4** - Given the constants in `Tuning::default()` changed in this story, when the story ends, then `## Notes` carries the table of old and new values with AC-1/AC-2 figures before and after, and `docs/wiki/architecture.md`'s tuning table is updated to match.

## Model guidance

Model: default. Oracle partition:

- **Settled**: 90%, `margin_px + 8`, the containment predicate. Read out.
- **Mechanical**: AC-3, AC-4.
- **Oracle-free**: nothing - the corpus is the oracle. But the corpus can be wrong: a "clip" on one file may be a mis-marked rect. The Feature Developer reports that as a finding with the file name; the orchestrator opens the image and decides, with the user, whether the manifest or the detector is wrong, and records which in `## Notes`. Never edit the manifest to make the test pass without that record.

## Out of scope

Per-reader special cases, any detection technique not already in
`cropper-core`, tuning beyond `Tuning::default()`'s existing fields, adding
corpus files (MC-018, or a follow-up chore).
