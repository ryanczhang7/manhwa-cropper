## Context

[MC-078](MC-078.md)'s held-out run (scored commit `c108bd1`) cut one column
of `n05`, `2025-10-26 12_13_16.png` (`toongod`, dark, 2560x1440):

- crop at margin 0: columns **974..1573**, rows 167..1400 (end exclusive);
- the user's mark: `973,167 600x1233`, columns **973..1573**;
- MC-078's frozen oracle: `T` 167, `B` 1400. The rows are exact and no
  furniture is kept; the only fault is the left column.

[MC-079](MC-079.md) moves it to `tuning` and names it in the zero-clip
suites' `KNOWN_CLIPS`, pinned to today's crop. This story removes it.

**It has the shape of [MC-073](MC-073.md).** There, MC-071's `n05`
(`2025-11-01 12_34_31.png`, also `toongod`) was cut by one column on the
left. The Lead PO measured that column (1006): a thin dark line (band median
10, share 0.999) beside bright art, read as margin by `Margin::belongs`
branch 1, and like the columns the user's marks leave out on
`Screenshot (3605).png` and `2025-10-20 15_37_25.png`. Shown the numbers and
a zoomed picture, the user ruled **"Box starts at 1007"**, and MC-073 became
a re-mark with no code change. A rule that kept that column would have moved
(3605) and `10_20` outward again (MC-070's candidate B).

**Nothing below is a finding.** No agent has measured this image.
Candidates:
- **Candidate A: the same seam.** Column 973 is a thin dark line beside the
  art, as MC-073's 1006 was. Then the user decides between a re-mark (the
  box starts at 974) and a fix.
- **Candidate B: art.** Column 973 is the art's own first column, which the
  page-column stage reads as margin. Then this is a fix, and the rule that
  keeps it must not move (3605), `10_20` or MC-073's `n05` outward.

**Before RED, the Lead PO measures** on `main` (after MC-079), in a scratch
worktree outside the repository: column 973's statistics over the mark's rows
and over the central band (median, range, share within tolerance of the site
tone and of its own median), the same for 972 and 974, which branch of
`Margin::belongs` stops the widening, and the comparison with MC-073's four
columns. A zoomed picture of the edge is shown to the user with the numbers,
and the user rules. The criteria below are **re-cut on that ruling before
RED**, as MC-073's were.

## Model guidance

Model: default. The Lead PO measures before RED and orchestrates; the Test
Developer writes RED; the Feature Developer writes GREEN if it stays a fix.

**Oracle partition.**
- **Settled, read it out:** the mark, as the user leaves or re-rules it;
  MC-078's `T` and `B`; MC-073's ruling and its four-column comparison.
- **A person's call:** whether column 973 is art (a re-mark or a fix), put
  with numbers and a zoomed picture; any `Tuning` field moving.
- **Mechanical, pin exactly:** AC-1's crop and list removals; AC-2's unmoved
  crops and stage rows.
- **Oracle-free, only if it is a fix:** AC-3's reproduction and control.

**Success condition, which can come out either way:** `n05`'s crop contains
its mark at both margins with its rows unchanged, nothing else moves, and the
integration command with `--no-fail-fast` is green. It **fails** on any
other moved crop, a clip anywhere, a threshold swept until `n05` passes, a
per-site rule, or a mark changed without the user's ruling.
