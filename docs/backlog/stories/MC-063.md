### Why this run needs its own furniture ruling, marks notwithstanding

The user marked the 25 as art boxes that run the visible height: every mark's
top is on row 115, 133 or 167, the browser-bar ends MC-051 ruled for these
readers, and the user reported no site header. It is tempting to take the
mark's edges as `T` and `B` and skip a ruling. **That would be wrong, for
three reasons:**

1. **A mark says where the art is, not where furniture is.** Of the 25 marks,
   18 end on row 1392 or 1400, the two taskbar rows MC-051 ruled, and **7 end
   between 1 and 26 rows above** the row the marks from the same kind of
   screenshot end on. The rows between are page gutter, which stays, or a
   site footer, which does not. Only a ruling can tell them apart. Scored
   against the mark, a crop that correctly keeps gutter would fail absence.
2. **MC-051's own oracle found one-row site footers on row 1399** on two
   `toongod` entries, and a one-row site header on a `rolia-scans` entry. The
   user's "no site header" was said while marking art, not while ruling rows
   exact to the pixel; it does not cover footers at all.
3. **It would turn every one-row marking difference into a clip.** With `T` =
   mark top, containment and absence together demand the crop start on
   exactly the mark's row. A crop one row below the mark is a clip, the
   absolute half of the bar, when the true furniture edge may be that very
   row. MC-051 kept the two oracles separate and checked them against each
   other (its AC-2a) for this reason.

So AC-1 repeats MC-051's blind ruling, four rows per entry (Open question 3).
What it does not need that MC-051 needed: no quantisation pass, because the
page starts with MC-051's version-3 magnifier (row steps, opens at the image's
left edge), and no flag previews, because there are no flags.

**Consequence worth stating before the run.** Because the marks run the full
height, the ceiling on most entries is tight: the crop must start on exactly
the ruled browser-bar end and end on exactly the ruled taskbar (or footer)
start, to the row. That is the same predicate MC-051 scored, exact to the row
as MC-050's was, and it is not loosened here: a tolerance chosen now, knowing
the marks, would be a threshold picked for this set.

## Definitions used by every criterion

MC-051's, with the denominators changed:

- **Scored commit**: the `main` commit whose release build is run, recorded
  with the harness's source hash **before** AC-3 runs. `git diff d2876f5
  <scored commit> -- crates/core crates/engine/src crates/app/src Cargo.lock`
  is pasted beside it; empty means the "What this score measures" paragraph
  stands.
- **The crop**: `process_file`'s outcome at `Tuning::default()` on the scored
  commit, release build. For `Cropped { rect }`, rows `rect.y .. rect.y +
  rect.h` (bottom exclusive). For `Flagged`, the whole image.
- **Clip**: the crop does not contain the marked rect on all four sides,
  columns included.
- **`T`**: the ruled browser-bar end or site-header end, whichever is lower
  down the screen (the larger row: the first row below all top furniture), 0
  if none. **`B`**: the ruled site-footer start or taskbar start, whichever is
  higher up the screen (the smaller row), the image height if none. "Ends" is
  the first row below a bar; "starts" is its first row.
- **Furniture-free**: `crop.y >= T` and `crop.y + crop.h <= B`, exact to the
  row. A one-row remnant is present.
- **Cause attribution**, fixed before any crop, as MC-051 fixed it: browser
  chrome if `crop.y < chromeEnd`; reader header if `headerEnd > chromeEnd` and
  `crop.y < headerEnd`; reader footer if `footerStart < taskbarStart` and the
  crop's bottom is past `footerStart`; taskbar if the crop's bottom is past
  `taskbarStart`; flagged if the outcome is `Flagged`.
- **Meets the bar**: no clip and furniture-free. The bar is **0 clips on 25
  of 25** (absolute) **and at least 23 of 25** meeting it: the brief's 9 in 10
  of 25 (22.5) rounded up, the arithmetic that gave MC-051's 18 of 19. The
  user confirms 23 of 25 before AC-3 (Open question 5).
