## Context

`docs/wiki/audits/app-window-2026-09-13.md`, evidence **E-6**, found eleven
surviving mutants in `gui.rs`'s `text_width`, `truncate_left` and
`truncate_right` — including replacing each function's entire body with a
constant. `replace truncate_left -> String with "xyzzy".into()` leaves the
whole suite green.

The reason is worth stating plainly, because it is the clearest piece of test
theatre the audit found. `path_label` paints the truncated string and then
calls `response.widget_info(|| WidgetInfo::labeled(WidgetType::Label, .., full))`,
which overwrites the node's value with the **full** path. The only test near it,
`a_long_output_path_keeps_its_whole_path_as_the_accessible_name`
(`crates/app/tests/gui.rs:356`), asserts exactly one node is named with the full
path — which is true whatever `truncate_left` returned, including the empty
string. `flagged_row` does the same for rows, so `truncate_right` is in the
identical position.

That test is honest about what it says it checks: the accessible name is what a
screen reader reads, and `accessibility.md` requires it. **It must not be
weakened or deleted by this story.** The gap is that it is the *only* assertion
in the area, so the truncation itself is pinned by nothing.

**The audit's `## Decided` is settled.** **Its `## Evidence` is not, and this
story rests on one claim in E-6 that the audit explicitly flags as
undemonstrated:** that this cluster is killable *without* a renderer, because
the truncated value is a `String` a test could compare directly. No such test
was written. `truncate_left` and `truncate_right` currently take `&Ui` and are
private. **Establish in RED that an observable shape exists** — and if it does
not, or if making one distorts the module, say so and hand the cluster to
MC-021's snapshot surface instead of forcing it. That is a finding, not a
failure.

The required gate that would fail if this story's artifact broke is **`unit`**
(`cargo test --workspace`), which is required for the repo.

## Acceptance criteria

- **AC-1** — Given a path wider than the space available, when the folder row is
  painted, then the text actually shown begins with U+2026 and its rightmost
  characters are the innermost folder — i.e. the leaf survives and the head is
  what was dropped (`docs/wiki/design/layout.md`, "Output folder row").

- **AC-2** — Given a path that fits the space available, when the folder row is
  painted, then the text shown is the path unchanged, with no U+2026 anywhere.
  *Control for AC-1: a truncation that always fired would satisfy AC-1 and be
  wrong. This criterion is what makes AC-1 mean something.*

- **AC-3** — Given the same over-long path, when the folder row is painted, then
  the node's accessible name is still the whole untruncated path.
  *This is the behaviour the existing test already pins; it is restated so that
  a change made for AC-1 cannot quietly cost it.*

- **AC-4** — Given a flagged row whose file name is too long for the width, when
  the list is painted, then the shown text ends with the separator and the full
  reason word, and it is the **file name** that carries the U+2026
  (`docs/wiki/design/components.md`, the "overflow" row).

- **AC-5** — Given the shipped painter mutated so that `truncate_left` returns
  `"xyzzy".to_owned()` unconditionally (`gui.rs:602`), when the new tests run,
  then at least one fails. And given it mutated so that `truncate_left`'s first
  comparison is `>` instead of `<=` (`gui.rs:603`), when they run, then at least
  one fails. *Two named survivors from the audit's E-6, used as the negative
  controls for this story. Record both failures under `## Gate probes`: whole-body
  replacement and a flipped boundary fail for different reasons, and a test suite
  that catches only the first has pinned existence, not behaviour.*

## Model guidance

Oracle partition for RED:

| Criterion | Kind | Instruction |
|---|---|---|
| AC-1, AC-2, AC-4 | **Settled** | `layout.md` and `components.md` already decide which end gives way and what the mark is (U+2026, one character). Read them out. Do not re-derive a truncation policy. |
| AC-3 | **Mechanical** | An existing behaviour being held. Pin it exactly as `tests/gui.rs:356` already does. |
| AC-5 | **Mechanical** | Two named mutations at two named lines. Apply, watch red, revert, paste. |

The open question is **shape, not behaviour**: how a test gets to see the shown
text at all. Leave that to whoever writes RED — they will have the constraint in
front of them and this file will not. Say in the handoff which of the options
was taken and what it cost, so MC-021 knows whether this surface generalises.

Whatever shape is chosen, it may not make the *accessible name* stop being the
full path. That is a design decision in `accessibility.md`, and changing it
would need the product owner, not this story.

## Out of scope

- The look-only survivors — colour, fill, stroke, vertical offsets. MC-021.
- The progress bar fraction (MC-023) and `shell::count` (MC-024).
- Changing what the truncation does. The rule in `layout.md` stands; this story
  makes it observable, it does not revisit it.
- Rewriting `text_width` or optimising the character-by-character search. It is
  called once per frame on a path.
- Font-metric-dependent assertions that would break when a font package updates.
  Assert the *shape* of the result (leading U+2026, which end survives), not an
  exact character count at an exact width.
- Weakening, skipping or deleting
  `a_long_output_path_keeps_its_whole_path_as_the_accessible_name`. If it seems
  to be in the way, that is a signal to stop, not to edit it.

### The shape that was chosen, and what it cost

The story left open **how a test sees the shown text**, and named three
candidates. The one taken is a fourth that dominates all three:

> **`egui_kittest`'s `Harness::output()` returns the frame's
> `egui::FullOutput`, whose `shapes` are the untessellated paint list. Every
> `Shape::Text` still carries the `Galley` egui laid out, so `galley.text()`
> is literally the string on the screen and `galley.rect.width()` is how wide
> it is.**

Against the three the story listed:

| Option | Verdict |
|---|---|
| (a) make `truncate_left`/`truncate_right` `pub` | **Not taken.** It widens `gui.rs`'s API for the benefit of tests, and it tests the *function* rather than what was *painted* - a painter that truncated correctly and then drew something else would still pass. AC-1, AC-2 and AC-4 all say "when the folder row is painted". |
| (b) split measurement from policy behind a `Fn(&str) -> f32` | **Not taken.** A new seam, a new module, `required_gates` would gain `coverage`, and "Out of scope" already discourages rewriting this code. Not needed once (c) works. |
| (c) read the painted text back out of the frame | **Taken**, and it needs **no production change at all**. The audit flagged its own E-6 claim - that this cluster is killable without a renderer - as undemonstrated. It is demonstrated, and more cheaply than the audit hoped: not one line of `crates/app/src/` moves. |

The cost is that this file reads a `Galley` and a rect, which is exactly what
`tests/gui.rs` says in its own module docs it never does. That is why the tests
are a separate binary with a module doc that states the different contract,
rather than appended to `tests/gui.rs`.

**The consequence is that RED ends green.** Every test below passes against the
untouched painter on its first run. See `## Handoff: RED -> GREEN`, "Why there
is no red to paste", for how the first non-negotiable is discharged instead.

### Edges covered

- **Zero**: `truncate_*` returning `String::new()` - rejected by the empty-stem
  and empty-tail clauses, exercised in the AC-5 control.
- **One**: exactly one U+2026, asserted by count, so a painter that marked both
  ends fails.
- **Boundary**: both directions of the fit boundary are in the suite - a string
  over it (AC-1, AC-4) and a string under it (AC-2 and the short row), which is
  what makes a flipped `<=` visible.
- **The whole thing minus one character**: the two loop comparisons in E-6
  produce a result that passes every text-shape clause, so `much_narrower`
  compares the shown width against the *same string painted in a 3000 pt
  window*. A ratio, never a character count, so a font update moves both sides
  together - `## Out of scope` forbids the other kind.

### Deliberately not asserted

- No exact character count and no exact width in points against the real
  painter. `## Out of scope` forbids them.
- Nothing about colour, fill, stroke or vertical offset, even though the same
  surface can see them. That is MC-021's; see the handoff's last note.
- Nothing about `text_width`'s internals or the character-by-character search.

### The production shape these tests pin

**No new production API. Nothing in `crates/app/src/` needs to change for this
story, and GREEN should expect to write no source at all.** What the tests do
pin, all of it already true at this commit:

```
crates/app/src/gui.rs
  pub fn paint(ui: &mut Ui, model: &Model, hovering: bool)     -- imported and called

crates/app/src/lib.rs
  pub struct Model { pub state: AppState, pub output_dir: Option<PathBuf> }
  pub enum AppState { Idle, Done { summary: RunSummary }, .. } -- both constructed literally
```

Behavioural facts the file leans on, which are **not** negotiable while these
tests stand:

- `path_label` and `flagged_row` must keep putting their text through egui's
  ordinary text painting - an `egui::Label`, a `RichText` or a `LayoutJob` -
  so that the frame's `FullOutput.shapes` contain an `egui::Shape::Text` whose
  galley holds the shown string. A painter that drew glyphs by hand, or that
  cached a tessellated mesh, would become invisible to every test here.
- An **Idle** window with a folder chosen paints exactly three strings. Add a
  fourth and `path_label_text`'s "there must be exactly one of it" assertion
  fails with the whole frame in the message. That is deliberate: identifying
  the path label by elimination is what stops the test from finding
  `Choose folder…`'s own U+2026.
- `flagged_row` must keep building each row as **one** `LayoutJob`, hence one
  galley. Split into two Labels and no painted string ends with ` — Blank`.
- `truncate_left` and `truncate_right` stay **private**, and `text_width` with
  them. Nothing here imports them; making them `pub` was considered and
  rejected (see the Test plan).

Not constrained, and GREEN's to choose: everything inside `truncate_left`,
`truncate_right` and `text_width`; where the ellipsis constant lives; the
character-by-character search and its cost.

### Lead PO ruling: `MUCH_NARROWER` stays

RED asked whether the width-ratio check overreaches, since it is what kills the
two *loop* comparison survivors, which AC-5 does not name. It stays, for three
reasons.

1. It is not the assertion `## Out of scope` forbids. That bars "an exact
   character count at an exact width". This is a ratio of two widths of the
   *same string in the same font*, one of them measured in a window wide enough
   that nothing gives way, so a font update moves numerator and denominator
   together. The margin is 0.533 (worst real case) against 0.75 (threshold)
   against ~0.99 (the mutant).
2. AC-5 names two survivors as the story's negative controls, not as its
   ceiling. The story's Context sets the target as E-6's cluster of eleven, and
   the ratio is what takes the count from nine to eleven.
3. Dropping it would hand two survivors to MC-021 - a story about *look*, whose
   instrument is a rendered image - when a text-shape test already kills them
   here. That is the wrong home for them.
