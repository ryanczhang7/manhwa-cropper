## Test plan

**The mechanism, stated as a claim with its control (oracle-free part).**
Read out of the stages on both screenshots (`trim_uniform` → `content_box` →
`trim_within` → `textured_box` → `page_column`): every stage up to
`textured_box` keeps the whole width, and **stage 3c, `flat::page_column`,
cuts the edge**. Its widest textured run ends on the last column with band
spread >= `min_line_spread` (`f20` 1515, `f09` 1536). The widening
(`extend_to_the_margin` / `Margin::belongs`) then stops on the next column,
for a **different branch on each**:

- `f20`, **branch 3**. 1516 has band median 255, so it carries the page edge's
  tone on, but it is page background over the band (share 0.980) **and** over
  the viewport rows (0.979), so branch 3 calls it margin. The white strip
  1516..1521 is cut, though the site (25) starts at 1522.
- `f09`, **branch 1**. 1537 has band median 15, within `uniform_tolerance` of
  the page-background tone (the site's 11) and not of the page edge (60), so
  branch 1 calls it margin. It is **not** page background over the band
  (share 0.882), and branch 1 never asks. The art edge 1537..1538 is cut,
  though the site starts at 1539.

Shown, not narrated, three ways:
1. the AC-4 generated pairs below: each cause on fails today, and each cause
   off passes today;
2. two mutations in a scratch copy of the tree, outside the repository and
   deleted afterwards. These are not proposed fixes:
   - **A**, branch 1 also requires `background`: the `f09` generated case and
     real `f09` (AC-1) go green, while `f20` (generated and real) stays red,
     short by 6;
   - **B**, branch 3 keeps every continuing column without reading the
     viewport: the `f20` generated case and real `f20` (AC-2) go green, while
     the `f09` generated case stays red, short by 2. Real `f09` then crops
     `0,178 2545x1210`, the whole width, so dropping branch 3's check
     outright is far too loose.
