## Context

The walking skeleton. Before any detector exists, the exe must take file
paths on the command line and put a file in the output folder, exercising
argument parsing, the exit-code contract and file writing end to end
(`architecture.md`, "manhwa-cropper" and decision 10). Nothing is decoded;
the bytes are copied. Argument parsing lives in `cropper-engine::args` so it
is unit-testable; `main.rs` only dispatches. The end-to-end test spawns the
built binary via `env!("CARGO_BIN_EXE_manhwa-cropper")`, which cargo provides
to integration tests of a crate with a binary target.

Gate that fails if this breaks: `unit` (the spawned-exe test and the args
tests run under `cargo test --workspace`).

## Acceptance criteria

- **AC-1** - Given a PNG file `a.png` and an existing empty directory `out`, when the exe runs with `--no-gui --out <out> <a.png>`, then `out/a.png` exists, its bytes equal the input's, and the exit code is 0.
- **AC-2** - Given `--out` names a directory that does not exist, when the exe runs with one existing input, then the directory is created, the copy is written and the exit code is 0.
- **AC-3** - Given an input path that does not exist, when the exe runs with `--no-gui --out <out> <missing>`, then nothing is written to `out` and the exit code is 1.
- **AC-4** - Given an unknown flag such as `--bogus`, when the exe runs, then nothing is written and the exit code is 2.
- **AC-5** - Given `argv` `["--no-gui", "--out", "D:/o", "a.png", "b.png"]`, when `cropper_engine::args::parse` runs, then it returns `Invocation { no_gui: true, out_dir: Some("D:/o"), inputs: ["a.png", "b.png"], summary_path: None }`; given `["--summary", "s.json", "a.png"]` it returns `summary_path: Some("s.json")`; given `["--out"]` with no value it returns an error.

## Model guidance

Model: default. Oracle partition: all **mechanical** - pin the exact
`Invocation` shape, exit codes and file bytes. Do not assert on stdout or
stderr; the exe is built with the Windows GUI subsystem (decision 10) and
those streams may be unattached.

## Out of scope

Decoding or cropping anything (MC-008), the run summary file (MC-011 and
MC-012), the fallback output folder when `--out` is absent (MC-012), the
settings file (MC-013), multiple inputs beyond parsing them (MC-011), the
window (EPIC-04).

**Spawning.** `EXE = env!("CARGO_BIN_EXE_manhwa-cropper")`. `run_exe(args, cwd)`
spawns with all three stdio handles nulled, polls `try_wait()` every 20 ms,
and after 10 s kills the child and returns `TimedOut`; `exit_code(...)` turns
that into a panic whose message names the AC ("exe was still running after
10s - it did not act on its arguments and exit"). That is the RED failure.
In GREEN each run should take milliseconds; the timeout only bites when the
exe opens a window instead of exiting.

**Scratch dirs.** The app crate has no `tempfile` dev-dependency and RED
cannot add one, so `Scratch::new(name)` builds
`std::env::temp_dir()/mc002-<pid>-<name>`, wipes any leftover, creates it,
and removes it in `Drop` (which also runs on panic unwind). Nothing is
written inside the repository tree.

**The PNG.** `sample_png()` is the real 8-byte PNG signature, an IHDR-shaped
chunk, 600 xorshift bytes (contains 0x00, 0xFF and everything between) and an
IEND trailer: 641 bytes. The exe does not decode it; it only has to copy it.

### The API the tests already import (not negotiable)

    cropper_engine::args::Invocation
        #[derive(Debug, Clone, PartialEq, Eq, Default)]
        pub struct Invocation {
            pub inputs: Vec<PathBuf>,
            pub out_dir: Option<PathBuf>,
            pub no_gui: bool,
            pub summary_path: Option<PathBuf>,
        }

    cropper_engine::args::ArgError
        #[derive(Debug, PartialEq, Eq)]   // Clone is allowed, not required
        pub enum ArgError {
            UnknownFlag(String),   // the flag as typed, e.g. "--bogus"
            MissingValue(String),  // the flag as typed, e.g. "--out"
        }

    cropper_engine::args::parse
        pub fn parse<I, S>(argv: I) -> Result<Invocation, ArgError>
        where I: IntoIterator<Item = S>, S: AsRef<str>
        // argv EXCLUDES the program name. main.rs feeds std::env::args().skip(1).

Rules pinned: `--no-gui` anywhere; `--out <v>` and `--summary <v>` take the
next item verbatim as a `PathBuf`, and a missing next item is
`MissingValue(<flag>)`; a later `--out` overrides an earlier one; any other
item starting with `--` is `UnknownFlag(<item>)`; every other item (including
`-` and `a--b.png`) is an input, in argv order; empty argv is
`Invocation::default()`.

Left unconstrained on purpose: single-dash items such as `-x` (the tests
never pass one); whether an `--out` value may itself start with `--`; a `--`
separator; repeated `--no-gui`; nested creation of more than one missing
`--out` level (AC-2 is tested with exactly one); the `Display`/`Error` impls
of `ArgError`; where inside `crates/engine/src/` the module lives, as long
as it is reachable as `cropper_engine::args`.

Exit-code contract pinned through the exe: 0 when the one input was written,
1 when the input could not be read/written at all, 2 on any parse error -
before anything is written and before any window is opened.

### Notes for the implementer

- `main.rs` currently returns `eframe::Result` and goes straight to
  `run_native`. The headless path has to run and exit before that; a parse
  error has to exit 2 before it too (`an_unknown_flag_exits_2_even_without_no_gui`
  passes no `--no-gui`).
- Do not rely on stdout/stderr for anything; the tests null all three
  handles and the exe is `windows_subsystem = "windows"`.
- The copy's file name is the input's file name (`a.png` -> `out/a.png`).
  Collision handling belongs to `naming.rs` in a later story and is not
  pinned here.
- `out` must contain only the copy after a successful run (`entries(out) ==
  ["a.png"]`): no summary or sidecar in `out`. The summary path is a
  separate flag and a later story.
- AC-3: the input is missing, `out` already exists and must stay empty.
  Whether `out` gets created when the input is missing and `out` does not
  exist is not tested.
- Relative `--out` and input paths resolve against the process cwd (the
  tests set `current_dir` to the scratch root). Plain `std::fs` does this.
- Scratch dirs are `%TEMP%\mc002-<pid>-<name>`; if a run is killed hard they
  are wiped on the next run of the same test.
- `crates/app/tests/window.rs` (MC-001) is untouched.
- Files touched in RED: `crates/engine/tests/args.rs` (new),
  `crates/app/tests/cli.rs` (new), this story's `## Test plan` and
