## Context

`docs/wiki/audits/app-window-2026-09-13.md` ran cargo-mutants over
`crates/app` and found 55 surviving mutants in `gui.rs` that change only a
fill, a stroke, a text colour or a position — including one
(`gui.rs:428 delete !`) that paints the **enabled** "Choose folder…" button in
disabled grey, and one (`gui.rs:269`) that discards the whole widget palette in
both themes. MC-015's test surface is the AccessKit tree, which carries text
and roles and no colour, so none of them is observable there. EPIC-04's
"## Follow-up, agreed 2026-09-13" named this as the first thing to close.

**The audit's `## Decided` section is settled — do not reopen it.** In
particular Decided-2: these mutants are killable by image snapshot tests and
**not** by AccessKit assertions. Do not spend RED trying to find a tree query
that catches a colour; there is none.

**The audit's `## Evidence` is not settled and this story depends on two of its
numbers.** Verify both before sizing:

- **E-7** says `egui_kittest` 0.36.2 declares `snapshot` and `wgpu` features.
  That was read from a manifest. Nothing was compiled. Whether a wgpu adapter
  is available under `cargo test` on this machine, whether a software fallback
  is needed, and what the feature costs in build time are all **unmeasured**.
  Establish this first; it decides whether the story is viable at all.
- **E-4** says `rounded_rect_outline` alone accounts for 30 of the 55, and that
  at least one of them (`gui.rs:642:68 replace / with *`) is **equivalent at
  the only call site that exists** — the clamp is inactive, so the painted
  pixels are identical and no snapshot can kill it. The audit checked exactly
  one mutant for equivalence. Do not read "55 survivors" as "55 tests".

The required gate that would fail if this story's artifact broke is **`unit`**
(`cargo test --workspace`), which is required for the repo. That is only true
if the snapshot tests actually run there — see AC-5, which exists precisely so
this story cannot end with tests that no required gate executes.

## Acceptance criteria

- **AC-1** — Given each of the seven window looks in
  `docs/wiki/design/components.md` ("Window-level states": idle-no-folder,
  idle-folder, drop-hover, processing, done, done-with-flags, error), when the
  window is painted headlessly, then the rendered image matches a committed
  reference image for that look.

- **AC-2** — Given the light theme and the dark theme, when the idle-with-folder
  look is painted in each, then each matches its own committed reference image
  and the two images differ. *Control: a run that rendered the same palette
  twice would satisfy AC-1 and prove nothing about theming; the two images
  being byte-identical must fail this criterion.*

- **AC-3** — Given the shipped painter mutated so that `folder_button` applies
  its disabled tokens when the button is **enabled** (`gui.rs:428`, delete the
  `!`), when the idle-with-folder snapshot test runs, then it fails. *This is
  the audit's E-3 headline survivor; it is the negative control for the whole
  story. Record the failure output under `## Gate probes`.*

- **AC-4** — Given the shipped painter mutated so that `widgets()` returns
  `Widgets::default()` (`gui.rs:269`), when the snapshot tests run, then at
  least one fails. *Second control, on a different mechanism: AC-3 exercises a
  per-widget override, this exercises the palette installed at startup.*

- **AC-5** — Given a clean checkout on the reference machine, when
  `bash scripts/gates.sh --gate unit` runs, then the snapshot tests execute and
  are counted — they are not skipped, not `#[ignore]`d, and not behind a
  feature flag that the gate command omits. *If the renderer cannot be made to
  work under the required `unit` gate, stop and put it to the product owner
  rather than parking the tests behind an optional gate: a suite no required
  gate runs is the trap `story-authoring` names by example.*

- **AC-6** — Given a reference image and a render that differ, when the test
  fails, then the failure names which look differed and writes the actual image
  and a diff to a path the developer can open. *A snapshot failure that says
  only "images differ" is not actionable and will be silently re-baselined.*

## Model guidance

Oracle partition for RED:

| Criterion | Kind | Instruction |
|---|---|---|
| AC-1, AC-2 | **Settled** | The seven looks and the two themes are `components.md` and `tokens.md`. Read them out. Do not invent an eighth look or re-derive a colour. |
| AC-3, AC-4 | **Mechanical** | Named mutations at named lines. Apply exactly those, watch the named test go red, revert, paste the output. One mutation, one run, one revert. |
| AC-5, AC-6 | **Mechanical** | An operational property of the gate and the failure output. Pin it exactly. |

There is no oracle-free criterion here, which is unusual and is the point: the
design documents already decided every value. The risk in this story is not
judgement, it is the renderer working at all — so spend the effort on E-7 and
AC-5, not on metric design.

Reference images are **committed artifacts that no human will look at twice**.
Whoever writes them must look at each one once, with their eyes, against
`docs/wiki/design/`, and say so in the handoff. A reference image generated
from a broken painter is a test that asserts the bug forever, and it is the
single most likely way this story goes wrong.

## Out of scope

- Anything in `crates/core` or `crates/engine`. The audit did not look at them.
- The truncation survivors (MC-022), the progress fraction (MC-023) and the
  `shell::count` survivors (MC-024) — separate stories, separate fixes.
- `gui.rs:687` (`RfdPicker::pick`), `gui.rs:723` (`CropperApp::ui`) and
  `main.rs:92` (`open_window`): accepted gaps under the audit's Decided-4 and
  Decided-5. Do not try to close them here.
- `main.rs:93 delete field viewport` (audit Decided-6): a real gap, deliberately
  unowned. Not this story.
- Chasing the survivor count to zero. Several `rounded_rect_outline` mutants may
  be equivalent (E-4); a story that adds tests until a number reaches 0 will add
  tests that assert nothing.
- DPI-specific or font-rendering-specific pixel assertions beyond what one fixed
  render size needs. Snapshot tests that fail when a font package updates are a
  liability, and MC-015 put DPI assertions out of scope for the same reason.
- Changing any painted value. This story pins the look that exists; if a
  reference image reveals the painter disagrees with `components.md`, that is a
  finding to report, not to fix here.

## Design notes

No new design. `docs/wiki/design/components.md`, `tokens.md`, `layout.md` and
`accessibility.md` are the specification, unchanged. The seven looks in AC-1 are
that file's "Window-level states" table, row for row.
