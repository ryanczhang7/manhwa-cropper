## Context

The brief's open question 1: the success criteria ("zero clipped panels",
"nine of ten need no fix") can only be measured on the user's own
screenshots with hand-marked expected rectangles. **No agent can complete
this story; the user supplies the files.** It is a `chore` under SCAFFOLD:
the user drops screenshots into `fixtures/corpus/` and fills in
`fixtures/corpus/manifest.json`; the Lead PO writes the manifest validator
test (a test file, under `crates/engine/tests/`) and a loader module under
`crates/engine/tests/common/` that MC-019 reuses. No production source is
written, so `## Scaffold inventory` lists none.

How the user marks an expected rectangle: open the screenshot in any editor
with a selection tool (Paint shows the selection's origin and size in the
status bar), select the tightest rectangle that contains all the artwork and
none of the chrome or gutter, and record `x, y, w, h` in pixels. For a
screenshot that should be left alone (all art, or mostly blank with no
confident panel), record `"expect": "flag"` instead of a rect.

Manifest shape (one entry per file):

    { "entries": [
      { "file": "chrome-dark-01.png", "expect": { "x": 412, "y": 131, "w": 1096, "h": 949 },
        "tags": ["dark-theme", "black-gutter", "png"] },
      { "file": "all-art-01.jpg", "expect": "flag", "tags": ["all-art", "jpeg"] }
    ] }

`fixtures/**` classifies as `test` in `paths.conf`, so the images may be
added during any phase that permits tests.

Gate that fails if this breaks: `unit` (the validator test is not ignored).

## Acceptance criteria

- **AC-1** - Given `fixtures/corpus/manifest.json`, when the validator test runs, then it parses, has at least 20 entries, every named file exists under `fixtures/corpus/`, and every file decodes with the `image` crate.
- **AC-2** - Given an entry with a rect, when validated, then `w >= 1`, `h >= 1`, and `x + w <= image width`, `y + h <= image height`.
- **AC-3** - Given all entries' tags, when validated, then the union covers every one of: `light-theme`, `dark-theme`, `white-gutter`, `black-gutter`, `all-art`, `mostly-white`, `png`, `jpeg`, `webp`; and every `all-art` and `mostly-white` entry has `"expect": "flag"`.
- **AC-4** - Given the corpus directory, when its total size is summed, then it is below 60 MB (so the repository stays clonable without LFS).
- **AC-5** - Given the loader in `crates/engine/tests/common/corpus.rs`, when `load()` runs, then it returns `Vec<CorpusEntry { path, expect: Expect::Rect(Rect) | Expect::Flag, tags }>` in manifest order.
- **AC-6** - Given the corpus, when validated, then at least one entry is a WebP whose RIFF payload chunk is `VP8 ` or `VP8X` wrapping a lossy payload (not `VP8L`), and when that file is run through `process_file`, then the output is a WebP whose pixels equal the *decoded* source pixels inside the rect. **Inherited from MC-009 AC-3** by the amendment recorded in `docs/backlog/stories/MC-009.md`; it is here because nothing in this workspace can *write* a lossy WebP and this is the story where a real one arrives.

## Model guidance

Model: default. All criteria are **mechanical** checks on files the user
provides. The only judgement - is the hand-marked rect right - belongs to
the user, and the validator cannot check it; MC-019's zero-clip result on a
wrongly marked rect will show up as a "clip" that the user must re-examine.

## Out of scope

Tuning any constant (MC-019), generating screenshots artificially (the
whole point is that they are real), a marking tool, more than the minimum
coverage the tags require.

### MC-009 AC-3 landed here (2026-09-11, approved by ryanczhang7)

AC-6 above is not new scope invented for this story. It is MC-009's AC-3,
deferred here because `image` 0.25.10 / `image-webp` 0.2.4 can only *write*
lossless WebP, so MC-009 could not author the fixture the criterion needed.
Reading lossy WebP works; the full evidence is in MC-009's `## Amendments`.

**The practical consequence for the user supplying the corpus.** AC-3's
`webp` tag is no longer satisfied by any WebP: at least one of them must be a
lossy one. In practice this costs nothing - WebP screenshots saved by browsers
and messaging apps are lossy by default, and a lossless WebP is the harder one
to come by - but it is now checked rather than assumed, which is the point.

MC-018 is still PLANNED, so adding a criterion here is not an amendment: the
freeze begins when a story leaves PLANNED.
