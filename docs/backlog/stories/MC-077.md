## Acceptance criteria

The oracle is the user's 10 marks, frozen on the day they are read back
(`## Notes`). Nothing here re-derives or adjusts a mark.

- **AC-1: the files.** Given the 10 drawn files, when they are copied into
  `fixtures/corpus/` under their own names, then each copy's SHA-256 equals
  the one recorded in `## Context`, and each is 2560x1440 by header.
- **AC-2: the entries.** The manifest has exactly one entry per drawn file,
  each with `split: "held-out"`; `expect` equal to the user's box
  (`{ x: left, y: top, w: right - left, h: bottom - top }`) or `"flag"`
  where the user flagged it; tags as MC-068's (theme, `png`, `site:<site>`,
  and `white-gutter` or `black-gutter` per the user's gap answer, none for
  "can't tell"). A test pins all 10 by name, as MC-068's `FRESH_HELD_OUT`
  does, and was watched to fail before the entries existed.
- **AC-3: the ceiling.** `MAX_BYTES` is 140 MiB, and the size test was
  watched to fail at 120 MiB with the 10 files in place.
- **AC-4: held-out is only fresh.** The 11 entries that are `held-out`
  before this story have `split: "tuning"`, and every `held-out` entry is one
  of the 10. A test asserts both, naming any entry that breaks either.
- **AC-5: the floors.** `MIN_HELD_OUT_MARKED` equals the number of the 10
  the user marks (not flags), so losing any is caught; `MIN_HELD_OUT_SITES`,
  `MIN_HELD_OUT_FLAGS` and `MIN_UNSEEN_SITES` are set by the user's ruling
  once the marks show which readers the 10 cover (Open question 2). Each
  constant's doc comment records the ruling.
- **AC-5b: tuning still holds with the 11 moved in.** When the `unit` and
  `integration` suites run, every tuning-suite requirement (zero clips on
  every marked tuning entry, flags flagged, crops pinned where a suite pins
  them) holds for the 11, or the entry is named in that suite's
  known-exceptions list. **Every exception is put to the user before RED
  ends.** No source file changes.
- **AC-6: the record.** `docs/wiki/corpus.md` gains the draw (steps, table,
  the scripts' hashes), the 11 moved to `tuning` with the new counts, the
  ceiling, and the floor rulings, and says what the fresh set can and cannot
  speak for (which readers, whether any flag entry, and that 10 entries make
  each miss worth 10 points of accuracy).

The one scored run on the fresh set is **not** this story. It follows as an
MC-071-shaped spike.

## Model guidance

Model: default. The Lead PO publishes the marking page and drives SCAFFOLD
(copy, manifest, `corpus.md`); the Test Developer writes RED.

**Oracle partition.**
- **Settled, read out:** the drawn list and hashes above; the user's marks
  once frozen; the user's ceiling, floor and exception rulings.
- **Mechanical, pin exactly:** AC-1's hashes and sizes, AC-2's entries,
  AC-3's ceiling, AC-4's moves.
- **No oracle-free part:** nothing here is measured or tuned.

**Success condition, which can come out either way:** the 10 are in,
held-out holds only them, and both test commands are green with every AC-5b
exception the user's. It **fails** if any drawn file is viewed or measured by
an agent before it is marked, if a file not in the table is added, or if a
mark is adjusted.
