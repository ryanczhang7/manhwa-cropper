## Context

The calibration corpus (MC-018) is 28 real screenshots and 21 hand-marked
rectangles, and it is the oracle for every accuracy claim this project makes.
The rule those rectangles were drawn to is written down in exactly two places -
MC-018's story, which is DONE and is a historical record, and the module doc
comment of `crates/engine/tests/common/corpus.rs` - and the wording in both is
**wrong in a way that makes correct marks look like mistakes**.

This story came out of MC-032's own suggestion ("Cheap to settle: open the nine
and look"). All 21 marked entries were rendered and read by eye on 2026-09-17
with the user ruling on the marks; the survey is in MC-032's `## Notes` and is
not repeated here. Three things fell out of it that belong to the corpus rather
than to any detector story:

**1. The marking rule's wording is too broad.** It currently reads "the tightest
axis-aligned rectangle containing all the artwork, **including any non-flat
overhang into the gutter**". Two marks the user confirmed as correct contradict
that as written:

- `Screenshot (2744).jpg`, bottom at row 1298: a caption box ("IF DELPHINE HAD
  BEEN ON THE 40TH FLOOR...") straddles the mark, and the mark is on the art
  edge with the box **outside** the rectangle.
- `Screenshot (2630).jpg`, top at row 224: the speech bubble from the panel
  *above* hangs down across the mark, and is **outside** the rectangle.

The rule the user has actually been marking to, confirmed by them on
2026-09-17, is narrower: **a panel's own overhang extends its rectangle; a
neighbouring panel's overhang, or a caption box sitting in the gutter, does
not.** Until that is recorded, the next agent reads the current phrasing, looks
at `Screenshot (2744).jpg`, and files a manifest bug against a correct mark.

**2. Two entries have diagonal gutters, and the tag for them is unused.**
`tests/common/corpus.rs` says `diagonal-gutter` and `overhang-text` "are valid
and exist so MC-019 can report on those cases separately". `diagonal-gutter` is
applied to **zero of the 28 entries**, and two need it: `Screenshot (93).jpg`
(top edge) and `2025-10-20 15_37_25.png` (bottom edge), both confirmed by eye
with the user.

This is not cosmetic. `Screenshot (93).jpg` is **MC-019's sole column miss**, at
+20 px on the right against an 11 px window, and the diagonal is why: when the
gutter runs diagonally the page's left and right edges are row-dependent, so no
single pair of columns is correct for the whole page. MC-019's RED recorded that
the miss is "structural, not a threshold away" without being able to say why.

**3. Diagonal gutters carry a tolerance that is recorded nowhere.** The user's
rule, stated for the first time on 2026-09-17: where the gutter is diagonal, a
mark on the **higher edge, the lower edge, or the middle** of the diagonal is
equally acceptable - it is not a hard line. `fixtures/corpus/manifest.json`
stores one exact rectangle per entry with no indication that a range was
intended, so the recorded rectangle reads as precise when it is not.

**Diagonal entries cannot be found automatically, and this story must not try.**
MC-032's `## Notes` records the attempt: per column, the row of strongest
vertical gradient near the mark, then the slope and fit of those rows against x.
It finds `2025-10-20 15_37_25`'s top edge clearly (-50.3 rows per 100 columns,
r2 0.47) and nothing else; `Screenshot (93).jpg`, identified instantly by eye,
scores 14.9 at r2 0.12, and the user's diagonal on `15_37_25` is its *bottom*
edge, which the instrument calls flat. Art texture dominates the gradient. The
two entries named above are the two a person confirmed, and this story tags
those two and no others. If a third is found later it is tagged by a person.

### Why this is a SCAFFOLD chore

`paths.conf` classifies `fixtures/**` as **test**. So the tag - the thing this
story changes - and the assertion that pins it are both test paths, and the
phase lock cannot separate them: the assertion cannot be written in RED and the
tag added in GREEN, because GREEN does not permit test writes. That is the
definition of one indivisible derivation, which is what `rules.md` allows a
`chore` to use SCAFFOLD for.

`## Scaffold inventory` is therefore about a story that changes **no production
source at all**. `check-boundaries.sh` only demands the inventory when a source
file changed, so an honest "none" is the correct entry, not a loophole.

Gate that fails if this breaks: **`unit`**, which is required for the whole
repo. `crates/engine/tests/corpus_manifest.rs` is deliberately *not*
`#[ignore]`d - it is the target that checks the corpus is well formed, it runs
under `cargo test --workspace`, and AC-1 and AC-3 below are asserted there. No
optional gate is load-bearing for this story, so `required_gates` stays empty.

## Acceptance criteria

- **AC-1** - *The diagonal entries are tagged, and the list is exact.* Given
  `fixtures/corpus/manifest.json`, when the corpus is loaded, then the entries
  carrying the tag `diagonal-gutter` are **exactly** `Screenshot (93).jpg` and
  `2025-10-20 15_37_25.png`. An entry missing the tag and an entry carrying it
  that is not in that list both fail, and the failure names the file and which
  of the two mistakes it is. *Control on the metric:* removing the tag from
  either entry must fail the test, and adding it to any third entry must fail
  the test - an assertion that only checks "at least one entry is tagged" would
  pass under both and is not sufficient.

- **AC-2** - *Every tag in the manifest is in the documented vocabulary.* Given
  the manifest, when the corpus is loaded, then every tag on every entry appears
  in the tag vocabulary recorded by AC-3's page, and an entry carrying a tag
  outside it fails the test naming the file and the tag. *Control on the
  metric:* adding a misspelt tag (`diagonal-gutters`) to any entry must fail,
  which is the defect this exists to catch - a typo'd tag is invisible today and
  silently belongs to no category.

- **AC-3** - *The corpus has one written source of truth.* Given the repository,
  when `docs/wiki/corpus.md` is read, then it records (a) the marking rule in
  the narrowed wording confirmed by the user - a panel's own overhang extends
  its rectangle; a neighbouring panel's overhang or a caption box in the gutter
  does not - with `Screenshot (2744).jpg` and `Screenshot (2630).jpg` named as
  the worked examples; (b) the diagonal-gutter tolerance, that any position on
  the diagonal is acceptable; and (c) the tag vocabulary AC-2 checks against.
  The module doc comment of `crates/engine/tests/common/corpus.rs` cites that
  page instead of restating the rule, and the page states that MC-018's original
  phrasing is superseded. Verified by review, not by a test: this AC is about
  where prose lives, and a test that a file contains a sentence pins the
  sentence rather than the meaning.

## Model guidance

Model: default. Oracle partition:

- **Settled, read out, never re-derived**: the two diagonal entries
  (`Screenshot (93).jpg`, `2025-10-20 15_37_25.png`) and the marking rule's
  narrowed wording. Both are the **user's rulings** of 2026-09-17, recorded in
  MC-032's `## Notes`. They are not measurements and are not open to
  re-derivation from pixels - an agent that "checks" them against an instrument
  will get a different answer, because MC-032 records that no instrument agrees
  with the eye here.
- **Mechanical**: AC-1 and AC-2, which want exact pinning. AC-3, which is prose.
- **Oracle-free**: nothing.

AC-1 and AC-2 are genuine RED: both assertions fail before the manifest is
touched, for the right reason (the tag is absent; the vocabulary does not yet
exist). Unlike MC-019 there is nothing to earn by probe here - watch them fail,
then make them pass.

**Do not add a third `diagonal-gutter` tag on your own judgement**, and do not
apply `overhang-text`. Both are a person's call, and the `## Context` says why.

## Out of scope

- **Re-marking any rectangle.** No value in `fixtures/corpus/manifest.json`'s
  `expect` fields changes in this story. The tolerance is *recorded*, not
  applied: MC-019's criteria are frozen and DONE, and `Screenshot (93).jpg`
  stays the accepted column miss it is.
- **Applying `overhang-text`**, or auditing which entries deserve it. The survey
  that would settle that has not been done, and a guessed tag is worse than an
  absent one.
- **A machine test for diagonal gutters.** MC-032's `## Notes` shows it does not
  work; re-running it is waste.
- **Editing MC-018.** It is DONE and is the historical record of how the corpus
  was built. AC-3's page says its phrasing is superseded; MC-018 itself is left
  alone.
- **Anything about the row axis.** That is MC-032, still parked.

## Test plan

Both assertions live in `crates/engine/tests/corpus_manifest.rs`, which is not
`#[ignore]`d and so runs in the required **`unit`** gate. No new gate, no new
test target, no production source.

| AC | Test | What makes it fail |
|---|---|---|
| AC-1 | `exactly_the_two_confirmed_entries_carry_the_diagonal_gutter_tag` | set equality against `DIAGONAL_GUTTER_ENTRIES`, reported as two distinguishable mistakes: a confirmed entry without the tag, and a tagged entry nobody confirmed |
| AC-2 | `every_tag_in_the_manifest_is_in_the_documented_vocabulary` | any tag on any entry that is not in the vocabulary table on `docs/wiki/corpus.md` |
| AC-3 | reviewed, not tested — but see below | — |

**AC-2 reads the vocabulary off the page rather than repeating it in Rust**,
and that is the one design decision here worth stating. A
`const KNOWN_TAGS: [&str; 11]` would have been the obvious shape and the
existing `REQUIRED_TAGS` is precedent for it — but it would be a *second copy*
of a list whose first copy is prose, and two copies of a corpus rule drifting
apart is the exact defect this story exists to remove (`## Context`, item 1).
So `documented_tag_vocabulary()` parses the markdown table that follows the
`<!-- tag-vocabulary -->` marker, taking any row whose first cell is a
backticked tag; the header and the `|---|` separator are excluded by their
shape rather than by counting lines.

That choice also buys AC-3 more than review. AC-3 says it is "verified by
review, not by a test", and (a) the marking rule and (b) the tolerance still
are — a test that a file contains a sentence pins the sentence, not the
meaning. But **(c) is now machine-pinned**: delete `docs/wiki/corpus.md`,
delete the marker, or delete a row, and the `unit` gate fails. Probe 4 below
shows that, and it is what distinguishes "reads the page" from "reads a const
and mentions the page in a comment".

Checked and deliberately not asserted: the converse direction, that every
documented tag is carried by something. `overhang-text` is documented and
applied to nothing on purpose (`## Out of scope`), so that assertion would be
false by design.
