## Context

The first story. It turns the empty repository into the three-crate Rust
workspace in `docs/wiki/stack.md` (Layout) and `docs/wiki/architecture.md`
(Components), fills in every gate command in `.claude/harness/project.conf`,
and proves each gate by breaking what it guards. `stack.md` is researched and
unexecuted by construction; this story is where every command in it runs for
the first time, so anything that has moved is corrected in both files. Runs
under SCAFFOLD (the bootstrap exception in `rules.md`), driven by the Lead PO.
The gate that would fail if this story's artefact broke: every required one.

Keep it to the toolchain and the gates. The example test in each crate is a
placeholder that proves the runner sees the crate, not a first slice of
product behaviour; the walking skeleton behaviour is MC-002.

## Acceptance criteria

- **AC-1** - Given the scaffolded workspace, when `bash scripts/gates.sh --gate lint` runs, then `cargo clippy --workspace --all-targets -- -D warnings` runs over all three crates and passes.
- **AC-2** - Given the scaffolded workspace, when `bash scripts/gates.sh --gate unit` runs, then `cargo test --workspace` discovers and passes at least one test in each of `crates/core/tests/`, `crates/engine/tests/` and `crates/app/tests/`, and the three `discovery` lines in `project.conf` succeed under `bash scripts/doctor.sh`.
- **AC-3** - Given the scaffolded workspace, when `bash scripts/gates.sh --gate coverage` runs, then `cargo llvm-cov` prints a coverage table matching the gate's `evidence` regex and the gate fails when a function with no test is added to `crates/core/src/lib.rs` (recorded in `## Gate probes`, then reverted).
- **AC-4** - Given the scaffolded workspace, when `bash scripts/gates.sh --gate build` runs, then `target/release/manhwa-cropper.exe` exists afterwards.
- **AC-5** - Given the scaffolded workspace, when `bash scripts/task.sh dev` runs, then an eframe window titled `Manhwa Cropper` opens, and an `egui_kittest` test in `crates/app/tests/` finds a label with that text without a display.
- **AC-6** - Given `.claude/harness/project.conf`, when read, then every required gate (`lint`, `typecheck`, `unit`, `coverage`, `build`) has a command, an `evidence` line and an existing `cwd`; `integration`, `format` and `mutation` are configured as optional; `slow` lines name `build`, `integration` and `mutation`; a `floor` on `unit` equals the count observed; and `BOOTSTRAPPED=yes`.
- **AC-7** - Given `.claude/harness/paths.conf`, when `bash -c '. .claude/hooks/lib.sh; classify <path>'` is run, then `crates/core/tests/trim.rs` and `fixtures/corpus/a.png` classify as `test`, `Cargo.toml`, `rust-toolchain.toml` and `crates/core/Cargo.toml` classify as `config`, and `crates/core/src/lib.rs` classifies as `source`.
- **AC-8** - Given the filled-in manifest, when `bash scripts/gates.sh --audit` runs, then it reports no missing command, no missing evidence line, no unknown gate in any `slow`/`floor`/`discovery` line, and no non-existent `cwd`.
- **AC-9** - Given each required gate passing, when the thing it guards is broken (tests moved aside for `unit`; a `let x: u32 = "s";` for `typecheck`; an `unwrap()` on an `Option` in a `#[deny]`ed position or an unused variable for `lint`; a broken `use` for `build`; the untested function for `coverage`), then that gate fails, and passes again after the revert - all pasted in `## Gate probes`.

## Model guidance

Model: default for every phase. Oracle partition for whoever scaffolds: every
criterion is **mechanical** - a command either produces the named output or it
does not. Nothing here is to be calibrated; the only judgement is whether a
gate's output shape differs from `stack.md`, in which case correct `stack.md`
and `project.conf` together and say so in `## Notes`.

## Out of scope

Any cropping, any image decoding, the `--no-gui` flow (MC-002), the settings
file, the design tokens (the window here is the empty eframe default), `cargo
mutants` beyond confirming it is either installed and configured or waived
with a reason, CI workflow changes beyond what the harness already ships, and
a `.dockerignore` (nothing is containerised).

## What it must deliver

- `Cargo.toml` (virtual workspace, `[workspace.dependencies]` with every pin from `stack.md`, `[profile.release]` as described there), `Cargo.lock`, `rust-toolchain.toml`.
- `crates/core` (`cropper-core`, lib, no dependencies beyond dev), `crates/engine` (`cropper-engine`, lib), `crates/app` (`manhwa-cropper`, bin + lib). Each with `src/lib.rs` (and `src/main.rs`, `src/gui.rs` for app) and one test under `tests/`.
- `.gitignore` for cargo (`/target`), plus `.claude/state/`.
- `project.conf` fully filled in per `stack.md`, with `BOOTSTRAPPED=yes`.
- `docs/wiki/stack.md` corrected wherever a command or version moved, with the "Unverified" header replaced by a dated "Verified by MC-001" note listing what changed.

  Cause, verified: Windows **Smart App Control** is on
