### The draw, done 2026-10-04 before anyone looked at a drawn image

Run once, by the script below, from **names, byte sizes and PNG headers
only**. No drawn file has been decoded, displayed or measured, and none may
be until the user has marked it (but see Open question 1). The SHA-256

1. **Pool.** Every top-level `.png`/`.jpg`/`.jpeg` in the folder: **360**

   extension (21 of the folder's files are in the corpus already) and the 11
   the user reported (MC-081's seven and the four repeats). **328** left.
2. **Whole-screen only.** Exactly 2560x1440 or 1920x1080 by the PNG header
   (IHDR, bytes 16..23): **328** (all 2560x1440).
3. **Order.** By `sha256("MC-083|2026-10-04|Eleceed|<file name>")`,

   timestamp is within 30 minutes of any corpus screenshot's, any of the 11
   reported, or any file already drawn (times read as UTC). This keeps each
   drawn screenshot out of every reading session the corpus or the user's
   report already holds; in a folder of reading sessions it is strict, and
   **305** were skipped before the tenth pick.
5. **Count: 10**, the first ten accepted. Chosen by the Lead PO for room
   under the cap, below.

**Reproduce** with bash, GNU coreutils 8.32 and GNU Awk 5.4.1, from the
repository root, on a corpus as `main` holds it at `4d9b1a0` or after MC-081
(the seven are excluded as reported either way):
`bash draw.sh "/c/Users/ryanc/OneDrive/Pictures/Screenshots 1/Eleceed" fixtures/corpus 10`.
The script (sha256 `c148d4f055aa56b0335806be8f52756f8ac43ef7f08ffb441453361a9c682a56`,
LF line endings) gave the list below. Earlier copies of it, differing only
in comments and in the `TZ=UTC` line, gave byte-identical output three
times, once under the machine's own time zone (CDT) instead of UTC; the
seed, pool rules and count never changed.

```bash
#!/usr/bin/env bash
# MC-084's blind draw. Reads names, byte sizes and PNG headers only.
# The seed string says MC-083: it was fixed before the story ids were
# assigned, and the draw was run once with it and never re-seeded.
# Usage: bash draw.sh <eleceed-dir> <corpus-dir> <N>
# Prints: the pool counts on stderr, the drawn list (rank, name, bytes, WxH) on stdout.
set -euo pipefail
DIR=$1; CORPUS=$2; N=$3
SEED='MC-083|2026-10-04|Eleceed'
export LC_ALL=C TZ=UTC

# The 11 screenshots the user reported on 2026-10-04 (MC-081's report).
REPORTED='2025-03-16 22_56_00
2025-03-07 00_20_37
2025-03-07 01_02_31
2025-03-16 22_48_01
2025-03-16 22_51_37
2025-03-16 22_53_39
2025-03-16 22_53_55
2025-03-16 22_54_13
2025-03-16 22_54_55
2025-03-16 22_51_49
2025-03-16 22_54_27'

# Width and height from the header. PNG: IHDR at bytes 16..23, big-endian.
dims() {
  local f=$1
  case "${f,,}" in
    *.png) od -An -tu1 -j16 -N8 -- "$f" | awk '{printf "%dx%d", $1*16777216+$2*65536+$3*256+$4, $5*16777216+$6*65536+$7*256+$8}' ;;
    *) printf 'unknown' ;;
  esac
}

tmp=$(mktemp -d)
trap 'rm -rf "$tmp"' EXIT

# Stems already in the corpus (by name without extension).
ls -- "$CORPUS" | grep -v '^manifest.json$' | sed 's/\.[^.]*$//' | sort -u > "$tmp/corpus_stems"
printf '%s\n' "$REPORTED" | sort -u > "$tmp/reported"

# 1. Pool: top-level .png/.jpg/.jpeg files.
total=0; inpool=0; whole=0
: > "$tmp/pool"
while IFS= read -r name; do
  total=$((total+1))
  stem=${name%.*}
  if grep -qxF -- "$stem" "$tmp/corpus_stems" || grep -qxF -- "$stem" "$tmp/reported"; then continue; fi
  inpool=$((inpool+1))
  wh=$(dims "$DIR/$name")
  # 2. Whole-screen only.
  if [ "$wh" = 2560x1440 ] || [ "$wh" = 1920x1080 ]; then
    whole=$((whole+1))
    bytes=$(stat -c %s -- "$DIR/$name")
    # 3. Order key: sha256 of "<seed>|<file name>".
    key=$(printf '%s|%s' "$SEED" "$name" | sha256sum | cut -c1-64)
    printf '%s\t%s\t%s\t%s\n' "$key" "$name" "$bytes" "$wh" >> "$tmp/pool"
  fi
done < <(ls -p -- "$DIR" | grep -v / | grep -iE '\.(png|jpe?g)$' | sort)
echo "top-level images: $total; after removing corpus and reported: $inpool; whole-screen: $whole" >&2

sort -t$'\t' -k1,1 "$tmp/pool" > "$tmp/ordered"

# Timestamps (epoch seconds) of the near-twin anchors: every corpus screenshot
# and every reported one whose name is a "YYYY-MM-DD HH_MM_SS" stamp.
{ cat "$tmp/corpus_stems"; cat "$tmp/reported"; } > "$tmp/anchors"

# 4 and 5. Walk the order; skip a file within 30 minutes of any anchor or of
# any file already drawn; stop at N.
gawk -F'\t' -v N="$N" -v ANCH="$tmp/anchors" '
  function stamp(s,   a) {
    if (match(s, /^([0-9]{4})-([0-9]{2})-([0-9]{2}) ([0-9]{2})_([0-9]{2})_([0-9]{2})/, a))
      return mktime(a[1] " " a[2] " " a[3] " " a[4] " " a[5] " " a[6])
    return -1
  }
  function near(t,   i) {
    for (i = 1; i <= na; i++) if (t - A[i] <= 1800 && A[i] - t <= 1800) return 1
    return 0
  }
  BEGIN { while ((getline line < ANCH) > 0) { t = stamp(line); if (t >= 0) A[++na] = t } }
  {
    t = stamp($2)
    if (t < 0) { skipped_unstamped++; next }
    if (near(t)) { skipped++; next }
    drawn++; A[++na] = t
    printf "%d\t%s\t%s\t%s\n", drawn, $2, $3, $4
    sum += $3
    if (drawn == N) { exit }
  }
  END { printf "near-twins skipped before the %dth pick: %d; unstamped: %d; drawn: %d; bytes: %d\n", N, skipped, skipped_unstamped + 0, drawn, sum > "/dev/stderr" }
' "$tmp/ordered"
```

## Open questions

1. **How each drawn screenshot's box is filled in before you mark it.**
   **Answered by the user on 2026-10-04: "Simple method + zoom"** (option
   2 plus the loupe, the recommended one). The options as put:
   1. *Start from the app's own crop.* Quick, but your marks would lean
      toward what the app already does, which defeats a fair test. Not for
      this set.
   2. *Start from a simple separate method:* the smallest box around
      everything that is not the site's flat background colour, with any
      edge where it disagrees with the app's crop flagged for a closer look.
   3. *Start from nothing:* you draw every box yourself, with a zoom loupe.

   The orchestrator recommended **2 plus the loupe**, and the user chose it. So
   the one computation it needs (a script reading each
   drawn image's pixels to make the starting box, and comparing it with the
   app's crop) is the only look at a drawn file allowed before marking: its
   output goes to the marking page and nowhere else, and this criterion's
   "no agent decodes a drawn file before it is marked" is read with that
   exception, recorded in `## Notes`. The marking page is published or
   updated by the orchestrator after the answer.
2. **The floors**, once the marks are frozen. Put to the user in plain words
   with the counts: how few marked screenshots, and how few different
   comic sites, the kept-aside set may have before the tests refuse it. If
   all 10 are one site, the "sites" floor can only be 1 (it is 4 today), and
   the set then speaks for that one site only.
