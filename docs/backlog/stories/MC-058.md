## Context

The follow-up [MC-057](MC-057.md) left out of scope. MC-057 added
`--no-fail-fast` to the `unit` and `integration` gates, because by default cargo
stops at the first test binary with a failing test and hides every suite after
it. The `coverage` gate has the same shape:

    gate | coverage | required | . | cargo llvm-cov --workspace --fail-under-lines 95 --ignore-filename-regex '...'

`cargo llvm-cov` runs the same non-ignored tests as `unit`, under
instrumentation, and it fails fast the same way. MC-057 argued `unit` would
already show every failure. That holds only when both gates fail on the same
tests. A test that fails only under coverage (timing under instrumentation is
the known way, see the `ci-factor` lines in `project.conf`) is reported one
binary per run, and each run costs over a minute locally, more on CI.

`cargo llvm-cov` has two flags that run every test:

- `--no-fail-fast`: runs all tests and still exits non-zero if any failed.
- `--ignore-run-fail`: runs all tests, writes the report, and **exits 0** when
  tests failed but the report succeeded. That would turn a failing test into a
  passing required gate, so it is the wrong flag, and this story says so where
  the next person will look.

A harness chore with no production code. It changes one gate command, so it
carries `## Gate probes`.

## Acceptance criteria

- **AC-1** — Given a change that breaks tests in two or more test binaries run
  by the `coverage` gate, when `bash scripts/gates.sh --gate coverage` runs,
  then the gate log contains the failures of every one of those binaries, not
  only the first. Negative control: before this story, the same change produced
  a log with exactly ONE `test result: FAILED` line.
- **AC-2** — Given such a change, when the gate runs, then `gates.sh` grades
  `coverage` FAIL and exits non-zero, exactly as before this story.
- **AC-3** — Given a clean tree, when the full `bash scripts/gates.sh` runs,
  then `coverage` PASSES with its `TOTAL` evidence line matching and its
  `--fail-under-lines 95` threshold unchanged, and `gates.sh --list` shows the
  new command with the same evidence line.

## Out of scope

- `--ignore-run-fail`, for the reason in `## Context`.
- `task | test`, which is a convenience for humans, not a gate.
