## Context

**The report (2026-10-04).** The user ran the app on their folder
`C:\Users\ryanc\OneDrive\Pictures\Screenshots 1\Eleceed` (2560x1440
screenshots; the app wrote its crops to the `cropped/` subfolder) and sent 11
of the app's crops. Many screenshots in that folder show **two browser
windows side by side**: the manhwa reader (`toongod`, Eleceed) on the left,
about columns 0..1820, and YouTube on the right. The orchestrator matched
each sent crop by sha256 to a file in `cropped/` and viewed the originals:

  instead of the manhwa page in the left window.
- **`2025-03-07 01_02_31.png` crops the manhwa** but keeps the bookmarks bar

  furniture.

  frame.

## Model guidance

Model: default. The Lead PO measures the pre-marks, orchestrates and drives
SCAFFOLD; the Test Developer writes RED, with MC-079's and MC-069's RED as the
template (same kinds of pins and lists).

**Oracle partition.**
- **Settled, read out:** the seven's names, bytes and hashes (`## Context`);
  the user's frozen marks and tags; the ceiling ruling.
- **Mechanical, pin exactly:** AC-1's files, AC-2's entries and counts, AC-3's
  constant, AC-4's lists and crop pins (measured in RED, not chosen), AC-5's
  unmoved crops.
- **Oracle-free:** none. Nothing is tuned, and the cause is not this story's.
- **A person's call:** the marks (Open question 1).

**Success condition, which can come out either way:** the seven are in as
`tuning` with the user's marks, the ceiling is 160 MiB, every failure of the
seven on `main` is named at its measured crop and the lists are exact in
both directions, and both test commands are green with nothing else moved.
It **fails** if a pre-mark enters the manifest without the user's
confirmation, if a mark is adjusted after it is frozen, if any of the four
repeats or any other file is added, if a pin is written for a crop that
differs from what the user saw without an explanation, or if any other crop,
stage row or list entry moves.
