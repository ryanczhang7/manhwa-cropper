## Context

Decision 7 in `architecture.md`: same file name from two source folders, or
a second run into the same output folder, must never overwrite. Explorer's
convention: `name (2).png`, `name (3).png`. Because the batch (MC-011) runs
files in parallel, names are planned up front, sequentially, before any file
is written: `naming::plan_outputs(out_dir, &inputs) -> Vec<PathBuf>` returns
one distinct, currently-free path per input in input order, accounting for
files already on disk and for duplicates within the batch. `process_file`
(MC-008) gains an explicit output path parameter so the planner decides
names and the codec only writes.

Gate that fails if this breaks: `unit`.

## Acceptance criteria

- **AC-1** - Given `out_dir` does not contain `a.png`, when `plan_outputs(out_dir, ["x/a.png"])` runs, then it returns `[out_dir/a.png]`.
- **AC-2** - Given `out_dir/a.png` exists, when planned for `["x/a.png"]`, then it returns `[out_dir/a (2).png]`.
- **AC-3** - Given `out_dir/a.png` and `out_dir/a (2).png` exist, when planned, then it returns `[out_dir/a (3).png]`.
- **AC-4** - Given two inputs `x/a.png` and `y/a.png` in one batch and an empty `out_dir`, when planned, then it returns `[out_dir/a.png, out_dir/a (2).png]` - the in-batch duplicate is resolved without anything on disk.
- **AC-5** - Given an input `Shot.PNG` that collides, when planned, then the result is `Shot (2).PNG` (stem and extension case preserved); given an input with no extension `notes`, then `notes (2)`.
- **AC-6** - Given `process_file` is called twice with the same input and the planned paths, when both complete, then both output files exist with distinct names and the first is unchanged by the second.

## Model guidance

Model: default. Oracle partition: all **mechanical**. Pin
`plan_outputs(&Path, &[PathBuf]) -> Vec<PathBuf>` and the exact ` (n)`
formatting (space, parentheses, ASCII digits).

## Out of scope

Recursion into folders, a limit on `n`, Unicode normalisation of file names,
cleaning up a partially written file after a crash.
