## Context

Decision 6 in `architecture.md` and "Where state lives": the one piece of
persistent state is the chosen output folder, in `settings.json` under the
config directory - `MANHWA_CROPPER_CONFIG_DIR` when set (tests always set
it), otherwise `directories::ProjectDirs::from("", "", "manhwa-cropper").config_dir()`.
A missing or corrupt file is the defaults; the app never fails to start
because of its settings. Engine only; MC-012 and MC-014 consume it. Ordered
before MC-012 because the headless fallback needs "was a folder ever
chosen".

Gate that fails if this breaks: `unit`.

## Acceptance criteria

- **AC-1** - Given `MANHWA_CROPPER_CONFIG_DIR` points at an empty temp dir, when `Settings { output_dir: Some(p) }.save()` then `Settings::load()` run, then the loaded value equals the saved one and the file is `<dir>/settings.json`.
- **AC-2** - Given the config dir has no `settings.json`, when `Settings::load()` runs, then it returns `Settings::default()` (`output_dir: None`) and creates nothing.
- **AC-3** - Given `settings.json` contains `{not json`, when `Settings::load()` runs, then it returns the defaults without error and leaves the file untouched until the next `save`.
- **AC-4** - Given the config dir does not exist, when `save()` runs, then the directory is created and the file written.
- **AC-5** - Given `MANHWA_CROPPER_CONFIG_DIR` is unset, when `Settings::config_dir()` runs, then it ends with `manhwa-cropper` and `config` path components (the `directories` layout on Windows) - checked on the path string, without writing there.

## Model guidance

Model: default. Oracle partition: all **mechanical**. Pin
`Settings { output_dir: Option<PathBuf> }` deriving `Serialize, Deserialize,
Default, Debug, PartialEq`, `Settings::load() -> Settings`,
`save(&self) -> io::Result<()>`, `Settings::config_dir() -> PathBuf`. Tests
that set the environment variable must not run concurrently with ones that
read it unset; use a single test binary with a mutex or pass the directory
explicitly through `load_from(dir)` / `save_to(dir)` and have
`load`/`save` be one-line wrappers.

## Out of scope

Any other setting (there are none in v1; decision 11), migrating old formats,
the window size, a settings UI.

## Test plan

One file, `crates/engine/tests/settings.rs`, twelve tests. Everything here is
an **integration** test at the crate boundary (`cropper_engine::settings`),
because every criterion is about a contract between the module and the
filesystem: there is no interesting pure logic to unit-test underneath it, and
nothing a GUI end-to-end test could add.

The five criteria are all **mechanical**. Every expected value is an exact
path, an exact directory listing, an exact JSON document or an exact `Settings`
value; there is no threshold anywhere and nothing to tune.

**The environment variable is the one real hazard.** A test binary runs its
tests on threads of one process, and one process has one environment - which is
why `std::env::set_var` is `unsafe` in edition 2024. So the file splits along
the line the `## Model guidance` draws:

- **Substance** (nine tests): AC-1 to AC-4 through `load_from(dir)` /
  `save_to(dir)`, which are handed the directory and read no environment at
  all. These say what persistence *does* and run concurrently with everything.
- **Wiring** (three tests): that `load`/`save` really go through
  `config_dir()`, and that `config_dir()` really reads the variable. These take
  a single `static ENV_LOCK: Mutex<()>` first - the set-it cases and AC-5's
  unset case take the *same* lock, so no test can observe another's value. The
  previous value is restored from `Drop`, which runs during a failing test's
  unwind, and the lock is taken with `unwrap_or_else(PoisonError::into_inner)`
  so one panic does not cascade into three misleading failures.

**Coverage of the shape.** Zero (no config directory at all; an empty one; an
empty settings file), one (a folder saved and read back), the `None` case
(defaults saved and read back), five kinds of corruption in a table, the
boundary AC-4 really faces (*two* missing directory levels, as
`%APPDATA%\manhwa-cropper\config` has on a first run), and the error path
(`save_to` under a path that is a file must return `Err`, not swallow it).

**Cost.** All twelve tests are a handful of small file operations. Measured at
**0.03 s for the whole binary** against a reference implementation during RED
(unoptimised, uninstrumented). There is nothing here that instrumentation or CI
hardware can push near any timeout.

**One control.** AC-3 only demands something if the five corrupt files really
are unreadable; if one of them parsed, AC-3 would be asserting that a *valid*
settings file is thrown away and the test would pass while the product lost the
user's folder. `the_five_corrupt_files_are_all_unreadable_as_settings` checks
both directions against a struct declared in the test file, so it does not
depend on the module under test being right. Its expected values were measured
outside the framework in RED and are in the handoff.

### The export shape the tests already pin

Stated as fact: a test imports these, so a different guess is a compile error.

```rust
// crates/engine/src/settings.rs, reached as cropper_engine::settings::Settings
pub struct Settings {
    pub output_dir: Option<PathBuf>,
}

impl Settings {
    pub fn config_dir() -> PathBuf;                        // associated, no self
    pub fn load() -> Settings;
    pub fn save(&self) -> std::io::Result<()>;
    pub fn load_from(dir: &Path) -> Settings;
    pub fn save_to(&self, dir: &Path) -> std::io::Result<()>;
}
```

- `crates/engine/src/lib.rs` needs `pub mod settings;`. The tests reach the
  type through the module path, so **no root re-export is required** (adding
  one is harmless).
- The struct is built with a literal, `Settings { output_dir: Some(p) }`, so
  the field is `pub` and the struct has **exactly one field**. A second field
  is a compile error in the test.
- Derives the tests require to *compile*: `Debug` and `PartialEq`
  (`assert_eq!` on `Settings`) and `Default` (`Settings::default()`).
  `Serialize`/`Deserialize` are required by *behaviour*, not by compilation -
  the tests never call serde on `Settings`, they read the file the module
  wrote. `Clone` is **not** needed by any test; add it if MC-014/MC-016 want
  it. `Eq` is not needed either.
- `save`/`save_to` return a `Result` whose error is `Debug` (one assertion
  formats it with `{result:?}`) - `std::io::Error` satisfies that.
- `load_from`/`save_to` are called as `Settings::load_from(&config)` with a
  `&PathBuf`, so `&Path` works by deref coercion. A generic
  `impl AsRef<Path>` would also compile; the story pins `&Path`, so use it.
- `#[must_use]` on `config_dir`, `load` and `load_from` is safe: every test
  binds their return values.

**Not constrained, and deliberately left to you:**

- Compact or pretty JSON - the assertions parse the file into a
  `serde_json::Value` and compare shapes, not whitespace.
- Whether `save_to` writes directly or writes-then-renames, *provided nothing
  is left behind*: two tests assert the config directory holds exactly
  `["settings.json"]` after a save, so a temporary file must be renamed or
  removed, not abandoned.
- The `ProjectDirs::from(...) == None` fallback. No test can reach it on this
  machine; pick something one line long (see "Watch items" below).
- The exact `io::Error` kinds and messages.

**AC-5, the `directories` layout.** `ProjectDirs::from("", "", "manhwa-cropper")`

```
C:\Users\ryanc\AppData\Roaming\manhwa-cropper\config
```

Components: `["C:", "\\", "Users", "ryanc", "AppData", "Roaming", "manhwa-cropper", "config"]`.
Last two, which is what the test asserts: `["manhwa-cropper", "config"]`.
`exists()` was `false` - it is `%APPDATA%` (Roaming), not `%LOCALAPPDATA%`, and
there is a `config` component under the application folder.

**AC-1, how `Option<PathBuf>` serialises** with a plain `#[derive(Serialize)]`
and no attributes:

| Value | `serde_json::to_string` |
|---|---|
| `Some(PathBuf::from(r"C:\Users\ryanc\Pictures\cropped"))` | `{"output_dir":"C:\\Users\\ryanc\\Pictures\\cropped"}` |
| `None` | `{"output_dir":null}` |

`to_string_pretty` of the first is `{\n  "output_dir": "C:\\Users\\ryanc\\Pictures\\cropped"\n}`.
Both forms satisfy the tests, which compare parsed `Value`s. What does **not**
satisfy them is `skip_serializing_if = "Option::is_none"`: the `None` case
must be `{"output_dir": null}`, a present null key, not `{}`.

**AC-3's control - the corrupt table.** Deserialised into
`struct { output_dir: Option<PathBuf> }`:

| Row | Text | Expected | Measured in RED |
|---|---|---|---|
| the criterion's own text | `{not json` | `Err` | `Err` - "key must be a string at line 1 column 2" |
| an empty file | (empty) | `Err` | `Err` - "EOF while parsing a value at line 1 column 0" |
| a bare null | `null` | `Err` | `Err` - "invalid type: null, expected struct Settings" |
| the right key, the wrong type | `{"output_dir": 42}` | `Err` | `Err` - "invalid type: integer `42`, expected path string" |
| a write that was cut off | `{"output_dir": "D:/pictures/out"` | `Err` | `Err` - "EOF while parsing an object at line 1 column 24" |

The control's other direction, so that it cannot be measuring "nothing parses":

| Text | Expected | Measured in RED |
|---|---|---|
| `{"output_dir": "D:/pictures/out"}` | `Ok(Some("D:/pictures/out"))` | as expected |
| `{"output_dir": null}` | `Ok(None)` | as expected |
| `{}` | `Ok(None)` | as expected |

That last row is why `{}` is deliberately **not** in the corrupt table: serde
treats a missing field of type `Option<T>` as `None` without any
`#[serde(default)]`, so an empty object is a *valid* settings file that means
the defaults. If `load_from` is written so that `{}` is an error, nothing in
this suite catches it, but nothing depends on it either.

### Watch items for GREEN

- **`create_dir_all`, not `create_dir`.** AC-4's test uses a config directory
  with *two* missing levels, because that is what the real first run faces:
  `%APPDATA%\manhwa-cropper\config` has neither component until something
  makes them. M2 and M3 above are the same single failure.
- **Do not memoise `config_dir()`** in a `OnceLock`, `LazyLock` or similar.
  Three tests change `MANHWA_CROPPER_CONFIG_DIR` at runtime and expect the
  next call to see it; a cached first value makes them order-dependent and
  flaky, and would pass or fail depending on which test won the race.
- **`load_from` and `save_to` must not consult the environment.** Nine tests
  call them while other tests are moving the variable around. If they read it,
  those nine become order-dependent.
- **`Cargo.toml` additions expected** in `crates/engine/Cargo.toml`:
  `directories = { workspace = true }` (already pinned at `6` in the root
  workspace and currently unused by any member), and `serde_json` **moved from
  `[dev-dependencies]` to `[dependencies]`** - the library itself now parses
  and writes JSON. Moving it up keeps it visible to the tests, so `tests/batch.rs`
  is unaffected. `serde` is already a regular dependency with `derive`.
  `Cargo.lock` will gain `directories 6.0.0`, `dirs-sys 0.5.0` and
  `option-ext 0.2.0`; that is expected and should be committed.
- **`#![forbid(unsafe_code)]`** is on `crates/engine/src/lib.rs`. Nothing in
  `settings.rs` needs `unsafe`: only `set_var`/`remove_var` are unsafe in
  edition 2024, and the library only ever *reads* with `env::var_os`. The
  `unsafe` in the test file is fine - integration tests are separate crates
  and do not inherit the attribute. It passed
  `cargo clippy --all-targets -- -D warnings` in the scratch crate.
- **Coverage.** `settings.rs` is small and the suite reaches all of it except
  the `ProjectDirs::from(...) == None` branch, which is unreachable on a
  machine with a home directory. Keep that fallback to a single expression -
  `.map_or_else(|| .., |dirs| ..)` - so it costs one uncovered region rather
  than a block, and the workspace stays over the 95% line floor.
- **The `unit` gate's `floor | unit | 47`** reads the first
  `test result: ok. N` line, which belongs to `crates/core tests/content.rs`.
  A new engine test binary does not move it.
- `cargo fmt --all` has been run; the file is clean under the `format` gate.
